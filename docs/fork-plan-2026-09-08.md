## Breakages, from source

**#606 (2026.8 and later).** `src/helpers/yaml2json.ts:21` loads `routes['developer-tools']`; the route is now `tools` (`ha-panel-config.ts:85`), so line 22 `whenDefined("developer-tools-router")` never resolves. `themes.ts:49` awaits it, `card-mod.ts:152` awaits `get_theme`, `refresh()` at `card-mod.ts:158` is never reached. Effect: no styles anywhere once the active theme defines any `card-mod-*-yaml` key. Plain `card-mod-*` keys and unthemed installs keep working, which matches the mixed reports. The separate TypeError (madmax1301, 2026-09-03) comes from `yaml2json.ts:8-16` building a detached `partial-panel-resolver` with `panels` as an array and calling `_updateRoutes()` unawaited; `partial-panel-resolver.ts:260-261` throws on `component_name`. `hass.panels` is still an object in 2026.9 (`types.ts:136-148`); the surrogate was always wrong and only now throws. Fix: UIX commit b014858, parse theme YAML with js-yaml (`load(yaml, {schema: YAML11_SCHEMA})`), validate the root is a mapping. This removes the only card-mod code that touches the router.

**#608 (`style:` never applies, `class:` works).** Same chain when the theme has `-yaml` keys (theme not named in the report). Second path: `theme-watcher.ts:57-65` rejects `themesReady()` after 30 s and nothing catches it; `card-mod.ts:86,102` call `_process_styles` without await or catch. `class:` is synchronous (`apply_card_mod.ts:180-185`) and never touches `get_theme`. Fix: js-yaml plus try/catch in `_process_styles` falling back to `{}` with one warning.

**#613 (no effect on newly added cards in sections).** Unconfirmed. Verified: `hui-section._createCardElement` (`:75-86`) still triggers the `_loadElement` hook; `_setElementVisibility` (`:276-294`) removes and re-appends, driving `_disconnect` and `connectedCallback`; in preview `hui-card.ts:192-196` rebuilds the element on every config change, so card-mod attaches to an element the editor discards. Reproduce in Phase 4.

**#614 (refresh loop on 2026.9.0).** Linked core issue #181149 is a Nabu Casa remote UI disconnect bug with reports from NGINX and Cloudflare users too. card-mod's only reload call is `ll-custom-actions.ts:39-46`, reachable only via `card_mod.action: clear_cache`. Likely misattributed; watch item.

## Phases

**Phase 0, baseline and inventory.** Cut `main` from `master`; apply the HA SOC baseline (protection, `.release.json`, release App, pinned actions, delete `stale.yml`); leave upstream branches on the fork untouched; `docs/` and decomment pass; bring `test/` docker-compose up in WSL against 2026.8.3 and 2026.9.1 with a theme carrying `card-mod-card-yaml`; run the inventory. Exit: green CI shell and a harness reproduction of #606.

**Phase 1, unbreak 2026.8 and 2026.9.** Merge `origin/2026.4.0-fixes`; js-yaml `yaml2json` with vitest cases (mapping, invalid YAML with line mark, `foo$` keys, YAML 1.1 booleans, non-mapping root); catch around `get_theme` and rejected `themesReady`; more-info to `ha-adaptive-dialog`; `ha-panel-tools` patch with type `tools` and a `developer-tools` alias so existing themes keep working; enable `ha-drawer`; `ha-adaptive-popover` in dialog selectors; remove `_createCards`; `hacs.json` `filename: card-mod.js`, `homeassistant: 2026.8.0`. Prerelease CalVer tag; verify on both cores. Exit: #606 and #608 symptoms gone with `-yaml` theme keys present.

**Phase 2, toolchain.** The table above in full; Babel removed (PR #609 intent); regenerated lockfile (closes #611); bundle size in release notes.

**Phase 3, performance.** PR #610 (`theme_index`, `icon_usage`, fast path) with unit tests; review points: `theme_index` must follow the `card-mod-theme` indirection, and the fast path must let `card-mod-<type>-debug` through. UIX icon hygiene, `get_theme` coalescing, `nextAnimationFrame`, `historystatechanged` and hash opt-out, entities guard, glance CSS refresh. Measure on the tablet against the Phase 0 baseline; target single-digit setTimeout per second.

**Phase 4, investigate and harden.** Reproduce #613 in the harness (sections view, add a card via the editor, save, reload) and fix the preview or visibility path; keep #614 tied to core #181149; add a hook-contract CI test that fetches the pinned frontend tag and asserts the patched private methods still exist (`_loadElement`, `_updateElement`, `_renderEntity`, `_handleUIConfigChanged`, `getConfigElement`, `ha-button[slot=secondaryAction]`) so a frontend release breaks CI rather than users; document the theme-key contract including the tools alias.
